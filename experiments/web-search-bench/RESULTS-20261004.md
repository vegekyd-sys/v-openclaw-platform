# web_search benchmark results — 2026-10-04 (round 1)

Run on V (outside the Gateway) with `run.mjs` / `answer.mjs` / `judge.mjs`. Judge:
`anthropic/claude-opus-5.5`, blind and shuffled per query. Answer model: V's default
`deepseek-v4-flash`. "Answer" = the final reply V would give from that tool output;
"e2e" = search time + answer time.

## Two query sets

- **bench** — the 49 committed queries (`queries.json`, 20 with answer keys).
- **real** — 60 most recent real V queries (2026-09-29 .. 10-04), kept on V only;
  not committed because they come from session transcripts.

The bench set is easier than real traffic: production Gemini runs p50 4.8 s on it
but 5.7 s on real queries (the journal says 7.8 s p50 for the whole call). Real
queries average 48 characters against 29, with many stacked keywords. **Use the
real set for latency.**

## Bench set (49 queries, 16 candidates)

Same ordering. Every working candidate got all 20 keyed facts right in the final
answer except Perplexity via the plugin (19/20), so the keys only catch broken
tools; the comparative scores are what separate them. Answer score vs today:
grok-4.20-nr +1.37, grok-4.3 +1.33, gemini-3.8-flash +0.80, parallel-free +0.73,
exa +0.67, keenable +0.63, gemini-3.8-flash thinking-low +0.45, sonar −0.04
(all CIs exclude 0 except sonar). Full table: `report.mjs` on `r1.jsonl,r2.jsonl`.

## What the numbers say

1. **Grading the tool output alone is misleading.** Raw-result plugins
   (Parallel, Keenable) score *below* today's Gemini at the tool level
   (parallel-free −0.71) but *above* it once V's own model writes the answer
   (+0.73). Gemini flash-lite's own summary throws away facts that V would have
   used. Only the answer stage measures what the user gets.
2. **Speed and quality are not a trade-off between today and raw-result search.**
   Parallel-free is better (+0.77) and about half the end-to-end time (4.4 s vs 8.2 s).
   The cost is prompt size: 4.5–5.5 k tokens per search instead of 1 k, which also
   lands in the session transcript.
3. **Grok is the quality ceiling but twice as slow** (16 s p50, 26 s p90).
4. **Bigger Gemini models are not the answer**: 3.8-flash is +0.5 and twice as slow;
   thinking-low makes it faster but drops source quality.
5. **Citation redirect resolution costs 1.0–1.5 s** of every Gemini search and still
   leaves opaque links in some results.
6. **Keyless tiers are not production-grade on V's IP**: DuckDuckGo failed 96/98
   (bot challenge), Firecrawl-free 50/98 (429), Baidu crawler hit a captcha on the
   second request. Parallel-free and Keenable keyless held up for ~350 calls each,
   but both are documented as rate-limited.

## Not yet measured

Tavily, Brave, Baidu Qianfan, Zhipu, Metaso (keys requested 2026-10-04) — all
raw-result providers, the class that won here. Exa, Parallel and Keenable with keys.

## Caveats

- One judge model; the "user message" given to V is the agent's search query.
- The answer stage runs DeepSeek without V's full system prompt and tools.
- Latency was measured from V at one time of day; each real query ran once.
