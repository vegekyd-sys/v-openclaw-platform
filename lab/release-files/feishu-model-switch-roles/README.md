# Session model switching for non-owners (V3: all V chat channels)

Scope: users already allowed to message V may use `/model` in their own session, including `/model vcodex` and `/model vcc`. No default model, model catalog or agent persona is changed.

V2 (live on V since 2026-09-24) did this for Feishu only (`providerId === "feishu"`). V3 applies the same rule to `feishu`, `telegram`, `dingtalk-connector`, `wecom` and `msteams`; Feishu behaviour is identical. `patch-runtime.mjs` upgrades a V2 runtime in place and patches a stock 9.1 runtime directly; both give the committed `command-auth-DmNN2m2f.js`.

The rule only acts where `commands.allowFrom.<channel>` (or `commands.allowFrom["*"]`) is configured. Setting `commands.allowFrom.<channel>=["*"]` alone would authorize every command surface for everyone; the patch narrows a non-owner on a listed channel to a whole-message `/model` prefix (anything else is reset-only, so `/new` and `/reset` still work). It does not restrict which configured model can be selected. Owners (`commands.ownerAllowFrom`, channel-prefixed) keep every command. Agent/global model-default writes remain restricted by OpenClaw's existing owner check. Channels without `commands.allowFrom` keep stock 9.1 behaviour, where the plugin's `CommandAuthorized` decides; DingTalk and WeCom compute it honestly since the v-experience patches (see `docs/v-experience.md` section 12).

Preflight: resolve the active Gateway runtime and exact `command-auth-*.js` target; confirm the same anchor in VLab and V. Run `patch-runtime.mjs CORE --check` before applying (`upgrade-v2` on V today). Apply only to a candidate runtime or under a VLab integration lease with a complete backup. `--apply` must be followed by `node --check` and a repeated `--check` showing `already`. The configuration change must retain the existing `commands.ownerAllowFrom` list and add only `commands.allowFrom.<channel>=["*"]` for the channels being opened.

Acceptance matrix, per channel: a non-owner sender can get `/model status`, switch to `vds`, `vcc`, and `vcodex` in their own session, and receive a visible response on each selected route; `/restart` and `/config` are not authorized; owner commands still work; ordinary chat and `/new` still work; direct or group conversations cannot modify agent/global defaults. Verify session metadata and runtime/harness, not only the acknowledgment text. Tests: `tests/model-command-roles.test.mjs` (patch and policy), `lab/candidate/{dingtalk,wecom,telegram}-model-roles.plan.json` (real channel plugins against fake platforms), `lab/candidate/feishu-model-switch-roles.plan.json`.

Rollback: restore the exact runtime file and config from pre-change backups. Runtime code and `commands.allowFrom.*` are restart-classified in the current runtime; shared VLab also has `reload=off`. Do not claim a hot reload. Production release is gated on actual shared VLab acceptance.
