# V card (v1)

What V Experience sends to channels that draw cards themselves — today the V
app (`v-voice/client`), later Feishu's own renderer. A V card is Feishu card
JSON 2.0 restricted to the subset below, plus `"v_card": 1`. Feishu is the
reference look, so a card that reads well in Feishu reads the same in the app.

```json
{ "schema": "2.0", "v_card": 1, "header": { … }, "body": { "elements": [ … ] } }
```

## Elements

| Tag | Fields used | Notes |
|---|---|---|
| `markdown` | `content`, `text_size` (`normal` / `notation` / `heading`) | Feishu markdown: `**bold**`, `` `code` ``, links, lists, `<font color>` |
| `hr` | — | The rule between the answer and the work view |
| `button` | `text.content`, `type` (`default` / `primary_filled` / `danger` …), `width`, `behaviors` | `behaviors[0]` is `{type: "callback", value}` or `{type: "open_url", default_url}` |
| `column_set` / `column` | `columns[].elements`, `flex_mode` | Button rows |
| `img` | `img_key`, `alt.content` | `img_key` may be a Feishu key or a V media source (`media://…`, a path on V) |
| `collapsible_panel` | `header.title.content`, `expanded`, `elements` | Folded steps |

`header` is `{ title: { tag: "plain_text", content }, template }` with Feishu
template colours (`blue`, `grey`, `green`, `orange`, `red`, …). Anything else is
drawn as plain text by the app and must not be relied on.

## Callbacks

A button's `callback.value` comes back to V unchanged. Kinds in use:

| `kind` | Value | Meaning |
|---|---|---|
| `question` | `{id, question, option}` | Toggle or pick an option of `ask_user` record `id` |
| `question` | `{id, submit: true}` | Submit the staged choices |
| `approval` | `{id, approvalKind, decision}` | Resolve an approval (`allow-once` / `allow-always` / `deny`) |

Plugin cards (the 「电脑」 handoff, credentials, night shift) keep the commands
they already post in Feishu (`/v-handback <id>`, …); the app sends them as the
tapper's message.

## Builders and fixtures

- `workCard({answer, view, phase, background, footer})` — V's reply; `view` is
  `createWorkView().snapshot()`.
- `questionCard(record, {state, staged, answers})` — an `ask_user` record.

`fixtures/*.json` are generated by `build-fixtures.mjs` and checked by
`tests/v-card.test.mjs`. The app copies them into its tests
(`client/VClientTests/Fixtures/vcard/`) and fails if it cannot draw one, so a
new element or field starts here, in both test suites, before any channel
sends it.
