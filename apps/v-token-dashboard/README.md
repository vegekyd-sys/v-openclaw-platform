# V Token 用量

在 V Platform worktree 里运行 `python3 apps/v-token-dashboard/server.py`，打开 <http://127.0.0.1:4386>。首次启动采集最近 30 个北京时间自然日。页面的「刷新数据」重新核算当前窗口，完成后原子替换上一次成功快照。调整采集窗口可用 `--days N` 并点击刷新。查询、切换维度和下钻均在本机快照完成。

通过本机已配置的 `ssh v`，以 openclaw 用户只读扫描各 Agent 的 OpenClaw SQLite（含留存归档）、Agent 专属 Codex home 和 V 关联的 Claude CLI 原生日志。采集进程独立于 Gateway。首次读取大窗口可能需要数分钟。采集按固定的响应时间上界截断，各数据源依次读取，稍晚落盘的记录可在下次刷新补入。本机 `~/.local/state/v-token-dashboard/snapshot.json.gz` 含计量数据、渠道身份和会话标识。该文件权限为 0600，不进入仓库。HTTP 服务仅监听回环地址。

## 用户排行

起止日期按北京时间自然日选择，包含首尾两天。「单日」「近一周」「近一月」分别展示 1、7、30 个自然日，以快照最后一天为准，最后一天只统计到采集截止时间。切换日期保留当前用户和会话。占比分母依次为所选范围内可归属用户总量、该用户总量、该用户在该会话的总量。搜索和分页只改变可见行。

每日柱形图可点选查看当天精确值。用量归属按个人、系统任务、未归属展示；分布图可切换渠道、模型、会话、任务类型与 Token 类型，并支持分页。

首页默认显示活跃渠道身份、这些用户涉及的去重会话数及可归属的 Token。点击姓名可看个人会话数、群聊或私聊名称；再点会话可看该用户在其中的模型用量。共享会话可以关联多人，全局计数按 Agent / Session ID 去重。同一人的跨渠道身份分别计数。

刷新时，`people.py` 在 V 上用对应飞书应用的只读权限核对 open_id 与通讯录、相关群成员显示名，仅保留本窗口内用户的匹配结果。群聊只根据消息父链或可识别的运行记录确定发送人。面板「用量归属」显示未归属原因及各项 Token。

品牌图使用 V 身份档案的 B 版头像为参考。运行时把定稿 WebP 放在 `--data` 目录下的 `v-brand.webp`，该目录与看板源代码分开维护。

## 夜班模式

夜班页显示所选日期内有计量的执行卡数、去重会话数、Token、占全平台比例、逐日趋势及模型分布。每日柱形总高表示平台 Token，其中高亮分段表示已识别夜班。点选日期或逐日切换可查看两者精确值及当天占比。派工卡来自夜班的阶段、内容项及审计记录。使用执行证据或 Workboard run ID 匹配子代理会话，并读取各 Agent 的现存和归档会话映射。专用夜班会话键中的卡 ID 也须命中派工账本。冲突及缺少证据的会话不计入。独立的夜班维度可与个人归属重叠，平台总量只累计一次；有夜班证据但无个人归属的用量归为系统任务。界面展示 Token，来源没有可核实的货币账单。

## 统计单位

- 每条可用计量记录携带北京时间日期、渠道、渠道账号下的用户标识、Agent 和实际 session ID、供应商、模型及用量。OpenClaw 优先采用 responseModel，Codex 使用 turn_context 中的模型。一个会话可以包含多位用户和多个模型。
- 用户根据结构化发送人和消息父子关系归属，单聊可回退到原生 direct user ID。显示名只作标签。群 ID、会话所有者和最后一个已知发言人都不能替代缺失的发送人。单次执行的子代理可通过结构化 sessions_spawn 成功回执追溯父请求，冲突的启动记录留在未归属。任务类型单列普通会话、子代理、定时任务及原生会话。渠道身份分别计算，同一人的跨渠道账号尚未关联。
- Codex 原生单次响应以供应商和 response ID 去重，原生日志与 OpenClaw 镜像通过 turn ID 对齐。有原生记录就用原生用量；同一 turn 只有旧式计数时使用累计增量。缺少原生记录时保留镜像。只有不冲突的映射可将原生记录归属到用户。
- `/vcc` 按 Claude 原生消息 ID 统计每次模型响应，包含工具循环和可关联的原生子代理。已核实对应的 CLI 会话摘要由原生响应用量替换，缺少对应原生记录时保留摘要。群聊用量随发起回合归属，缺少依据时列入未归属。
- 常规会话以供应商响应 ID 去重，老格式回退到事件身份。纯投递和自动化伪消息不计作模型调用。无请求标识的历史记录无法作供应商级去重。用量记录数包含旧式计数增量和镜像回退，与精确请求数有区别。
- 默认总量采用来源报告的 totalTokens / total_tokens，缺失时使用分项之和。普通输入、缓存读取、缓存写入互斥，推理属于输出。若上报分项与总量有差异，页面披露记录数。未归属和系统任务都进入总量。
- 看板覆盖指定范围内当前仍可读取的 V 会话和 Agent 原生 Codex 用量。主机独立 CLI、隔离 relay、已清理记录和未被来源记录的调用不在分母中。页面显示未归属 Token、缺失文件和零值/缺用量消息数。

## 正式版更新

正式入口为 https://v-usage.tianyi.live/ ，公众可直接查看姓名和用量统计。Cloudflare Worker 从私有 R2 桶读取专门生成的公开快照。公开链接与普通看板使用相同的用户显示名、群聊和私聊标题、模型、渠道及用量。用于关联的原始渠道身份和内部会话 ID 在发布时转换为稳定代号。页面保留 noindex。

采集机的 launchd 每 30 分钟检查一次，数据截止时间超过约 6 小时即通过 SSH 对 V 只读核算最近 30 个北京时间自然日。关机或网络中断期间，线上继续提供上一次成功版本，采集机恢复后补采。先上传带版本的全量数据，最后替换公开首页数据；两次上传均成功后写本机发布回执。采集和姓名解析在 V 上完成。下载中断或 SHA-256 校验失败时，同一轮最多下载三次，复用已完成的快照。发布失败时保留上一版公开数据，下一次检查重试。打开、切回页面或点「检查更新」会检查已发布版本，前台停留时每 5 分钟检查。用户排行和会话先载入，全平台与夜班明细在后台补齐。

采集端需要 Python 3、Node、可用的 `ssh v` 和有该桶写权限的 Wrangler 4。状态目录以 0700 保存，包含 `snapshot.json.gz`、`v-brand.webp` 以及首次发布时自动生成的 `public-ids.key`（稳定代号使用的本地随机密钥）。在应用目录执行以下命令；`STATE` 指向该目录。

```sh
node edge/publish.mjs assets "$STATE"
wrangler deploy --config edge/wrangler.toml
python3 sync.py --data "$STATE"
```

发布目标是独立 Worker 和采集机定时任务。页面发版及数据刷新都不需要重启 V Gateway。线上可从页面「数据截至」核对最新版本；本机 `published-public.json` 另记上传完成时间。手工立即刷新使用 `python3 sync.py --force --data "$STATE"`。

将已合并的应用放在独立发布目录后，用 `python3 edge/install-agent.py --app /absolute/app --data "$STATE" --wrangler /absolute/wrangler` 安装采集任务，日志位于 `$STATE/sync.log`。首次安装前通过 Wrangler 为正式域创建独立的私有 R2 桶 `v-token-usage-private`。网页静态资源的部署与快照发布可独立进行。
