# V Token 用量

在 V Platform worktree 里运行 `python3 apps/v-token-dashboard/server.py`，打开 <http://127.0.0.1:4386>。首次启动采集最近七个北京时间自然日。页面的「刷新数据」重新核算当前窗口，完成后原子替换上一次成功快照。调整窗口可用 `--days 30` 并点击刷新。查询、切换维度和下钻均在本机快照完成。

通过本机已配置的 `ssh v`，以 openclaw 用户只读扫描各 Agent 的 OpenClaw SQLite（含留存归档）以及 Agent 专属 Codex home。采集进程独立于 Gateway。首次读取大窗口可能需要数分钟。采集按固定的响应时间上界截断，各数据源依次读取，稍晚落盘的记录可在下次刷新补入。本机 `~/.local/state/v-token-dashboard/snapshot.json.gz` 含计量数据、渠道身份和会话标识。该文件权限为 0600，不进入仓库。HTTP 服务仅监听回环地址。

## 用户排行

首页默认显示活跃渠道身份、这些用户涉及的去重会话数及可归属的 Token。点击姓名可看个人会话数、群聊或私聊名称；再点会话可看该用户在其中的模型用量。共享会话可以关联多人，全局计数按 Agent / Session ID 去重。同一人的跨渠道身份分别计数。

刷新时，`people.py` 在 V 上用对应飞书应用的只读权限核对 open_id 与通讯录、相关群成员显示名，仅保留本窗口内用户的匹配结果。群聊只根据消息父链或可识别的运行记录确定发送人。面板「用量归属」显示未归属原因及各项 Token。

品牌图使用 V 身份档案的 B 版头像为参考。运行时把定稿 WebP 放在 `--data` 目录下的 `v-brand.webp`，该目录与看板源代码分开维护。

## 统计单位

- 每条可用计量记录携带北京时间日期、渠道、渠道账号下的用户标识、Agent 和实际 session ID、供应商、模型及用量。OpenClaw 优先采用 responseModel，Codex 使用 turn_context 中的模型。一个会话可以包含多位用户和多个模型。
- 用户根据结构化发送人和消息父子关系归属，单聊可回退到原生 direct user ID。显示名只作标签。群 ID、会话所有者和最后一个已知发言人都不能替代缺失的发送人。单次执行的子代理可通过结构化 sessions_spawn 成功回执追溯父请求，冲突的启动记录留在未归属。任务类型单列普通会话、子代理、定时任务及原生会话。渠道身份分别计算，同一人的跨渠道账号尚未关联。
- Codex 原生单次响应以供应商和 response ID 去重，原生日志与 OpenClaw 镜像通过 turn ID 对齐。有原生记录就用原生用量；同一 turn 只有旧式计数时使用累计增量。缺少原生记录时保留镜像。只有不冲突的映射可将原生记录归属到用户。
- 常规会话以供应商响应 ID 去重，老格式回退到事件身份。纯投递和自动化伪消息不计作模型调用。无请求标识的历史记录无法作供应商级去重。用量记录数包含旧式计数增量和镜像回退，与精确请求数有区别。
- 默认总量采用来源报告的 totalTokens / total_tokens，缺失时使用分项之和。普通输入、缓存读取、缓存写入互斥，推理属于输出。若上报分项与总量有差异，页面披露记录数。未归属和系统任务都进入总量。
- 看板覆盖指定范围内当前仍可读取的 V 会话和 Agent 原生 Codex 用量。主机独立 CLI、隔离 relay、已清理记录和未被来源记录的调用不在分母中。页面显示未归属 Token、缺失文件和零值/缺用量消息数。
