## 0. 结论

1. **现在 V 被问「你是谁」，会主动说自己「跑在 OpenClaw 上」。** candidate 里用 V 的字节、V 的提示文件和 V 的技能，问了 4 次（/vds 和 /deepseek，私聊和群聊各一次），4 次都这样说。例如 /vds 私聊答：「我现在跑在 OpenClaw 2026.9.1 上（Codex runtime……）」。
   顺带发现：4 次里有 3 次把主人名字写错，写成「天翼」「天一」。

2. **模型每轮收到的是一摞互相打架的身份。**以主力 /vds 为例，从前往后依次是：
   1. 「You are a coding agent running in the Codex CLI… led by OpenAI」；
   2. 「You are a personal agent running inside OpenClaw」；
   3. 「## OpenClaw Agent Soul — OpenClaw loaded these files… they are the canonical definitions of who you are」；
   4. SOUL.md 里的「I am V」；
   5. AGENTS.md 文件头的「Makaron Workspace Entry Point」；
   6. MEMORY.md 里的「V is Tianyi's AI partner **inside OpenClaw**」。

   只有第 4 条说 V 是 V。其余要么给了别的名字，要么把 V 放进 OpenClaw 里面。

3. **OpenClaw 字样的 token 很少，问题出在位置。**
   - 叙述性的 OpenClaw 语境每轮约 450–750 token，只占 /vds 一次请求固定前缀（约 6–7 万 token）的 1% 左右。
   - 但这些字样集中在**第一句话、身份段标题、`/status` 首行**，是模型判断「我是谁」最先读到的地方。
   - 另有约 740 处 `openclaw` 出现在路径里（技能 location、`/home/openclaw`、`makaron-openclaw/.openclaw-local`）。这些是功能性的，改不了，也不需要改。

4. **最大的几处都不用改 OpenClaw 核心。**
   - /vds 的底座身份句在 V 自己维护的 DeepSeek 模型目录里。
   - 「OpenClaw workspace context」这层包装是 V 自己的补丁加的。
   - MEMORY.md 和 AGENTS.md 是工作区文件。
   - 真正要打核心 dist 的，是 Codex 插件的第一句身份句、`/status` 首行，以及 PI 路径（如果不用文本替换插件的话）。

5. **系统提示之外，还有这些地方也带 OpenClaw：**
   - 工具描述，例如 `browser` 的「via OpenClaw's browser control server」、`gateway_exec`、`automations`；
   - 工具返回值，例如 `session_status` 首行「🦞 OpenClaw 版本」；
   - 内部事件提示：跨会话消息「routed by OpenClaw」、重启恢复、cron 回合说明、Workboard 派卡「Work on this OpenClaw Workboard card」；
   - 用户可见文案：飞书审批卡「OpenClaw 改动」、任务卡「Gateway 已重启」、语音页「OpenClaw Agent 没有完成」、钉钉和企微的兜底提示；
   - v-core 和 memory 目录。

   详见第 3 节。

6. **顺带发现一个比去 OpenClaw 化更值钱的问题。**/vds 线程里技能清单发了两遍：
   - OpenClaw 的紧凑清单 6.1 万字符；
   - Codex 原生清单 3.1–6.3 万字符，里面还混着 10 个和 V 无关的 openai-curated 插件技能根目录。

   另外，DeepSeek 路径每次请求都直接带上 43 个工具的完整 schema，9.4 万字符，约 2.4 万 token，并没有按需加载。收拾技能清单时可以一起处理，每次请求能省 1–2 万 token。

最值得先改的 10 项见第 5 节。

## 2. 两类「OpenClaw」

### 2.1 功能性的：改名会坏，只能改周围的说法

| 类别 | 例子 | 说明 |
|---|---|---|
| CLI 命令 | `openclaw config set`、`openclaw skills workshop …`、`openclaw nodes status`、`openclaw secrets store …` | V 自己的运维要用。可以加一句「V 平台的命令行叫 `openclaw`」，命令照写 |

### 2.2 纯语境的：可以改

- **身份和自我介绍**：S1、C1、C7、W10、P8、X1/X2、I18 系统 agent 人设（「You are OpenClaw, the system itself… a small, tidy hermit crab」）。
- **把运行时说成 OpenClaw**：「OpenClaw will deliver it」「OpenClaw routes」「generated by OpenClaw」「so OpenClaw stays silent」「routed by OpenClaw」「OpenClaw restored the progress card」「This is an OpenClaw cron automation turn」。
- **文档指向**：`## Documentation` 里的 docs.openclaw.ai、GitHub 源码、「OpenClaw behavior questions: docs first」。
- **段标题**：`## OpenClaw Control`、`## OpenClaw Agent Soul`、`## OpenClaw Skills`、`## OpenClaw Agent Workspace Instructions`、REDLINES 的「## OpenClaw System Files」。
- **用户可见的品牌**：「🦞 OpenClaw <版本>」「OpenClaw 改动」「Gateway 已重启」「OpenClaw Agent 没有完成」「OpenClaw bindings 配置」。
- **「Gateway」作宿主角色名的叙述**：「this Gateway host」「stalls the Gateway」「重启 Gateway」。建议统一叫「V 主服务」或「V 主机」，配置键和日志串照旧。

## 7. 风险和要注意的事

- **反向声明压不住第一句。**工作区里的声明位置在后面，DeepSeek 可能还是跟着第一句走。所以 #3、#4 才是关键，#2 只是兜底。
- **改 Codex developer instructions 会触发全量刷新。**已有线程会收到 C15 那条 policy 刷新消息，缓存失效一次。C15 必须和 C1 同一个补丁，否则刷新消息本身又把 OpenClaw 写回去。
- **字符串被比较的地方**：C12（`startsWith`）、P4（全等）、I10、I11（剥离逻辑）、U18（跨包 `startsWith`）。改的时候生成方和解析方要一起改，并兼容旧字符串。
- **V 仍然要会运维自己。**OpenClaw 文档、`openclaw` 命令、Gateway 配置键是 V 修自己的工具。改写只改「我是谁」，不能删掉「底层是 OpenClaw、命令叫 openclaw」这个事实。第 6 节的运维题就是防这一点。
- **worker 读第二份配置**（记忆 v-worker-config-second-file）：文本替换插件两边都要启用，否则 /deepseek 不生效。
- **Control UI 资源是 immutable 缓存**：P5 改了内容不换文件名，用户永远看不到。
- **升级**：所有 dist 补丁在 9.4、9.5 升级时都要 rebase（记忆 release-artifact-rebase-trap）。
