# Voice 输入暂停与上游恢复

## 问题与复现

生产用户截图显示 `Seeduplex upstream session failed`。生产只保留了聊天文本与通话起止，没有保存供应商错误码，因此不能确认这次用户通话的具体上游错误，也不能将其判定为通话时长上限。

在生产主机的独立 Voice 测试进程中，使用真实豆包上游与合成语音复现：旧版建立连接后停止输入音频，约 72.4 秒收到 `55000000`，消息中包含 `52000033 / AudioServerNoAudioInputTooLongError`，随后直接关闭通话。旧版正常按节奏输入的约 20.3 分钟、6 次模拟后台任务测试没有该错误。模拟后台任务只返回固定测试结果，没有实际发送任何外部消息。

供应商要求无音频时发送 `input_audio_mute.commit`、恢复时发送 `input_audio_unmute.commit`；输入按实时节奏发送，5xx 应恢复连接。参考：[豆包接入必读](https://docs.volcengine.com/docs/DoubaoVoice/access-mustread?lang=zh)。真实端点还验证了新 WebSocket 必须先 `session.create`，携带原 `session.id` 能保持原会话；直接发送 `session.update` 会被拒绝。

## 修复边界

- Voice 服务检测输入暂停，发送供应商静音事件；恢复音频前取消静音。输入以 20ms 分包节奏发送，并补偿轻微定时抖动。
- 仅对输入超时、5xx、连接中断进行有限恢复，每 60 秒最多 3 次；鉴权、参数及并发配额错误停止重试。
- 重连保持 Voice 与上游会话身份、后台 run 和工具去重状态；只有尚未发送的工具结果与播报排队。已发送的动作、旧音频和问候不重放。服务器返回不同会话身份时停止恢复。
- 挂断取消所有恢复计时器；旧连接的迟到事件不影响新连接。取消播放期间只忽略与该取消事件匹配的无活动回复错误，不吞掉其他错误。
- 将原 100/256 次的累计工具调用限制改为并发限制和有界的近期去重记录，避免健康长通话仅因累计次数结束。
- 私有日志仅增加固定错误分类、数字错误码、通话年龄与恢复次数，不保存原始协议、音频或任意供应商错误消息。

只修改 Voice 入口发布文件与测试，不修改 Gateway、Worker、共享配置或其他服务；不需要重启 Gateway。生产尚未发布此补丁。

## 验证

- 定向回归 162 项通过，涵盖真实本地 CLI 子进程、所有权、工具执行、后台任务、输入/播放、H5 状态与发布文件冻结。
- 虚拟时钟验证 3 小时暂停；压力验证 5,000 次已完成工具调用，去重与待执行集合有界。它们不是 3 小时真实设备验收。
- 真实上游验证 100 秒输入暂停后继续识别；后台等待中断开并恢复原会话；完成结果在恢复期间返回后只交付一次。
- 候选桥接器实际运行 21.9 分钟无错误，含 100 秒输入暂停和 4 次模拟后台调用。最终代码的独立实际运行为 15.2 分钟，含 100 秒输入暂停、4 段合成语音请求与 3 次模拟后台调用；第一次结果恰好在强制断线的恢复期间返回，原会话在约 5.6 秒后恢复，结果仅交付一次，各检查点的工具结果队列均为空，输入队列不超过一个 640 字节音频帧。这里的后台结果是固定测试内容，不代表真实日历查询。
- 自有浏览器加载真实产品页面、使用合成麦克风：AudioContext 暂停 100 秒后查本人日程成功；两次断线后正常继续对话；语音 `end_call` 等播放耗尽后回到空白拨号状态。日历为真实 Voice 本地 CLI；Gateway 调用在该测试中被禁止。
- 未收集真人原始音频，尚未进行实体 iPhone 上的长时复验。私人数据与具体会话证据不进入 Git。

授权合入后通过现有 Voice 入口控制器发布，在无活跃通话时仅切换 Voice 服务。验收须再次检查本人日程、插话、挂断、输入暂停恢复，并确认 Gateway 进程身份未变化。
