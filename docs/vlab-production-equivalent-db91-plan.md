# VLab 生产等价数据库修复验收

2026-09-08：用户批准在 VLab 腾出空间、对齐生产条件、复现并修复；不包含本轮生产部署。

## 不偏移的目标

保留生产已接受的 Worker 亲和性与 UM 关闭基线，解决数据库冷打开、多进程写锁和运行中重启恢复。不能用缩小数据库、降低总负载、关闭完整性保护或仅健康检查来替代成功。

## 执行顺序与门槛

1. 只读盘点 V/VLab 硬件、资源限制、运行版本、数据规模、实例所有权与空间。清理仅限确认无进程、配置、回滚引用且可删除的具体旧测试资源；保留证据清单。
2. 独立 worktree/分支、VLab 数据盘实例，登记 owner、端口、commit。重负载/共享集成操作须独占协调；不停止其他任务。
3. 使用最新生产一致性备份，不对活跃 SQLite 文件直接裸拷贝。敏感数据仅在授权测试环境内；凭据、聊天正文不入 Git 或报告。数据库、配置、二进制分别记录散列与允许差异。
4. 对齐 Worker min=1/max=15/slots=3、实际 main/subagent 设置、UM 关闭、亲和性开启、原生启动检查和恢复路径。资源不足必须明确记录，不能宣称等价。生产机器人与有外部副作用的任务只以独立账号或受控回放运行。
5. 先基线复现：数据库打开细分阶段；热/冷 Worker、完整冷启动、后台竞争与进行中重启。不得对仍有其他实例运行的宿主全局清缓存。
6. 定位后做最小修复；同一数据快照、同一负载、同一配置跑 A/B/A 对照。原有 5 新会话、5 工具回访、30 热请求和 10 轮 C5 保留，同时加入生产级后台负载及多 Agent。
7. 验证真实 Agent 正文、唯一编号的真实 toolCall/toolResult、无锁错误与丢任务；重启须核验最终回复及不重复副作用，不接受仅 session ID 保留。统计排队、实际活跃、阶段时延、首字、完整回复、错误及资源消耗，保留全部失败。
8. 私有候选通过后提交集成与独占渠道验收，报告环境差异、复现率、修复前后与残余风险。生产发布另行授权。
