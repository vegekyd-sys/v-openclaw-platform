# Voice 播放修复候选（2026-10-07）

用户反馈：小何在 iOS Safari 重复播放，最近通话卡顿；每次拨号重复授权。卡顿是首要验收项。当前修复仅源码分支，不改变共享 VLab 或 V。

## 改动

- 小何与 Grok 的 PCM 输出从主线程逐帧 BufferSource 排期改为 AudioWorklet 连续 FIFO，增加最多约 120ms 的启动/欠载缓冲。消费过的 PCM 不在欠载时重放；真实相同波形保留。
- 使用设备首选音频采样率，工作线程将 24kHz PCM 转到实际输出率；麦克风仍持续采集并转到 24kHz。
- 拨号/接通音效复用本次通话的 AudioContext，挂断仍释放麦克风和音频资源。
- 系统暂停音频时保留有界队列，页面点击恢复原 AudioContext，不重新拨号。实际播放回执用于队列容量、清空隔离和告别排空。
- 每通电话发出的音频带单调序号，仅拒绝同一传输序号重复；不比较 PCM 内容。提供完成边界与欠载、重复帧、队列高水位统计。

序号不会识别上游 provider 产生的两个不同事件是否重复了同一段声音。因此 iOS 重复播放的实际根因仍需真机复验，不能仅凭此补丁宣称解决。

## 验证

136 项相关本地测试通过，无 skip。覆盖 24/44.1/48kHz、50/60ms 到达间隙、欠载不重放、合法相同 PCM、长输出、有界容量、清空后迟到回执、暂停恢复、告别排空和共享音效上下文。

另用真实 Chromium 与 WebKit（iPhone 模拟）加载生产的 worklet source；合成 48,000 个 24kHz PCM 输入样本，在主线程阻塞 250ms 时得到完整 96,000 个 48kHz 输出样本，中间空洞为零、欠载为零。WebKit 控制台无错误；Chromium 仅诊断页 favicon 404。此检查是音频图处理证据，不是语音模型、物理输出或 iPhone 真机听觉验收。

## 仍待验证

- Safari 真机：小何/Grok 长回答不卡顿、不重复，插话清空、后台切回、挂断后重拨。
- 真正的音频收到→处理→扬声器输出时序；上游重复事件与系统播放路径。
- Safari 麦克风网站权限属于浏览器策略。网页不能以本地存储替代授权，也不会靠闲置期间持续录音绕过权限。站点设为允许后是否复用权限仍需真机核对。

本补丁没有改变工具选择与复杂任务委派策略。线上原常用工具通过 tools.invoke 直接调用；工具内部是否再使用模型取决于具体工具实现。
