## 根因与补丁

`current` cron 用原群作为来源和结果投递目标，实际执行仍进入独立的 `agent:…:cron:…:run:…` 会话。原有展示只覆盖人类消息、排队请求、跨会话消息、子任务回报和语音任务，没有为 cron 执行创建展示归属；独立会话本身也没有可用的飞书外部绑定。最终投递正常，不代表过程已经可见。

候选在 cron 完成准入及投递解析后，用来源会话的 session ID、生命周期版本、账号、目标及话题进行精确校验。受理时显示自动续接锚点，执行器实际进入时启动原生卡；该次运行 ID 和独立执行会话的公开进度事件更新同一张卡。原始提示词、拼接历史、推理、工具参数和工具输出均不进入展示。

最终结果在原有 cron 结果归档、静默判断、目标校验及内容转换之后，交给这张原生卡投递。真实消息 ACK 才标记成功。失败保留原卡和原结果重试，已有发送权时不切换另一发送器；不重跑模型。消息工具已确认发送、静默、取消和超时各有对应收尾。Gateway 重启时，尚未经过最终投递判断的模型原始输出不会被直接补发。

每轮续接独立持有卡片，新的人类对话和其他续接不会结束它。续接卡不附加原有单槽的全会话后台汇总行，避免其他任务结束时把仍运行的续接标为“后台任务已结束”；普通人类对话、跨会话和语音卡保留原汇总行为。未来尚未开始的定时任务不会冒充正在运行。本补丁不改变调度时间、业务修复逻辑、collector 的超时或并发策略。
