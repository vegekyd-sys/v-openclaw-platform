# 子任务收尾积压修复与验证

本补丁修复持续后台任务导致的 requester settle wake 积压，并让子任务状态检查不再把整段任务内容加载到 Gateway 主线程。已按用户授权合入 dev（集成提交 `c7dc979276cd`），合并后 22 项回归通过。共享 VLab 集成验收进行中，生产 V 尚未部署本补丁。

## 根因与改动

旧逻辑先检查主会话是否还有未结束的子任务，之后才判断已结束批次是否需要通知。Workboard 持续有任务运行时，即使已结束的任务全部不需要通知，它们仍保留待唤醒状态。后台逐条检查这些记录，每条检查又可能同步加载整个子任务注册表；500 毫秒缓存从读取开始计时，慢读会使缓存刚加载完就失效。

补丁保留原来的相连批次和冻结批次选择规则，先检查选中批次是否存在必须通知的任务。没有通知责任的已结束批次直接通过原有持久化回调完成收尾；需要通知的批次继续等待后代任务结束，沿用原来的代次、幂等键、重试和投递流程。正常保留的任务记录和结果不会因这条快速收尾路径被删除；原先显式要求 `retireAfterSettle` 的记录仍由原有生命周期逻辑退役。

`hasDescendantRunAwaitingSettle` 改用现有的状态字段投影，不加载 task、结果正文等完整 payload。投影补齐 `delivery.disposition`，并与完整加载器保持无需通知状态和 generation 的规范化一致，避免把已永久失败、主动不投递或已挂起的通知误判为未完成。缓存有效期从读取完成后开始计算；本进程持久化更新仍立即刷新缓存。

审阅入口是 [补丁生成器](../../lab/patch-subagent-settle-backlog.mjs)。三个发布文件由捕获的原始代码确定性生成，候选计划以原始文件 SHA 校验基线，拒绝覆盖不同版本。

## 验证结果

本地 22 项测试通过；独立候选环境额外运行真实 Node SQLite 与当前 runtime 的 Kysely 编译和执行代码，共 24 项通过、0 失败。外部投递边界使用测试替身，不调用模型或发送飞书消息。候选使用私有合成数据库，共享 VLab PID 在测试前后均为 `656845`，receipt 报告共享实例未改变。

| 场景 | 结果 |
| --- | --- |
| 125 条无需通知的已结束记录，加持续运行的子任务 | 旧代码保留全部积压；补丁清零，收尾检查无全表读取、无通知投递 |
| 连续完成 1,000 个后台任务 | 每次完成后待唤醒数均为 0，任务记录仍保留 |
| 恢复历史积压，再次重启加载 | 积压保持为 0 |
| 正常通知新旧行为对照 | 96 组场景的投递、重试、代次、落盘状态完全一致 |
| 混合批次和连接两个通知任务的无需通知任务 | 保留原来的批次关联；仍只投递一次 |
| Yield 冻结批次和语音 continuation | 保留原代次、直接投递、可见回复要求和 continuation 参数 |
| 并发回调、新代次、持久化失败 | 无重复投递；旧代次不清除新代次；写入失败回滚并可重试 |
| 后代状态投影 | 覆盖跨进程读取、缓存刷新、嵌套任务、旧代次、超时、挂起、永久失败及非规范记录 |

候选规模为 **2,854 条、45,751,232 字节合成 payload**。最后一次运行中，投影结果为 **1,010,137 字节**；完整读取 284.49 毫秒，投影读取 156.16 毫秒。相同数据库下，旧代码的 125 条无需通知记录扫描耗时 2,797.33 毫秒、完整读取 6 次，扫描后仍有 125 条积压。修复后的 125 次需要等待的状态检查共 865.59 毫秒，按真实时钟读取两次投影；125 条无需通知的积压完成持久化收尾耗时 **61.41 毫秒**，无注册表读取。再次从 SQLite 加载后待唤醒数为 0，2,854 条任务记录和 3 条运行中任务均保留。这些是候选单次观测，不代表线上响应延迟保证。

精确输入 hash、三个发布文件的前后 SHA、测试计数和耗时保存在 [验证记录](subagent-settle-backlog.evidence.json)。原始候选 receipt 为 `candidate-33e5f3d1-cd58-4c69-a01e-57447fc8b8dc`，位于本 worktree 的 `tmp/candidate/`。候选执行时 HEAD 为 `7553f482f4b4`，增加了真实 SQLite 旧代码对照，实际测试内容由 `inputFiles` 固定；交付提交前逐一复核这些文件的 hash。
