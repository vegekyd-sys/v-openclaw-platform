# 投影重建从最后一个有效投影接着算（F4，2026-10-17）

## 结论

- #405 之后，原地改写不会再让投影变脏。但下面几种追加仍会把投影标脏：
  - 分叉：parentId 不是当前叶子；
  - 回退或切换：叶子控制；
  - 旁路追加：渠道回复审计。
- 以前只要投影脏了，就从会话根整段重建。2.6 万行的会话每次要读、要解析全部行，主线程还要分块删掉、再写回全部 active/FTS 行，期间读者看到“正在重建”的时间达 4–7 s。
- 现在这几种追加会把状态标为 `needs_rebuild = 2`，意思是“脏，但已投影的前缀完好”。reconcile 遇到这种状态，按下面三步走：
  1. 只重放 indexed_seq 之后的新行；
  2. 从新叶子往上走，找到与旧活跃路径的交汇点；交汇点在最近一次压缩检查点之前或之后都可以；
  3. 新投影 = 旧投影里交汇点及之前的部分 + 新路径上的节点。主线程在一个写事务里应用这份增量。
- 只要有一项事实无法从新行和旧路径证明，就走原来的全量重建。

## 什么时候可以接着算

只有追加器（`createTranscriptIndexAppenderInTransaction`）在投影原本是最新的情况下标脏，才写 2。下面这些写入方仍然写 1，意思是“前缀可能变了”：
- 改写回退：改了导航字段或投影事实；
- 事件 JSON 更新；
- 整会话替换；
- 新会话复制；
- 存在未分类行；
- schema 迁移；
- 本补丁上线之前留下的脏状态。

投影处于 2 时，只要再经过上面任一写入方，就会被改回 1。所以“2 意味着前缀完好”在所有写入路径上都成立。

增量计划（在 reconcile worker 线程里，使用一个只读快照）必须同时满足以下条件，否则返回空，走全量：

- 旧投影的形状与状态一致：行数等于 active_event_count，位置连续，最大 event_seq 不超过 indexed_seq；没有未分类行；有新行。
- indexed_seq 时刻的 leafId 能证明：从 indexed_seq 往回读最多 256 行，找到最近一条非旁路的 canonical 行，它必须正好是旧活跃路径的最后一个节点。中途如果遇到叶子控制，或者遇到没有 parentId 的 canonical 行，就退回全量。
- 最近一次 reset（如果有）必须在旧活跃路径上。这时旧路径节点“是 reset 的后代”，当且仅当它的位置不早于 reset 的位置。
- 按 `scanSessionTranscriptNavigation` 的规则逐条重放新行，规则逐条照搬：reset 之后的父节点归一化、叶子控制的覆盖、旁路追加对 appendParentId 的处理、没有 parentId 的 canonical 行、穿过叶子控制解析 canonical 父节点。只要重放需要一个既不是新节点、也不在旧活跃路径上的节点（包括旧的旁支节点、没有 identity 的 id、指向后面行的引用），就退回全量。
- 新行里出现 reset、无效叶子控制、id 重复、新叶子为 null、路径断开，都退回全量。
- 增量（删除 + 新增）超过 4,000 行，退回全量，避免主线程写事务过大。

应用增量时（主线程，一个写事务），先复核以下几项，任何一项变了就拒绝，worker 随即对这个会话做全量重建：
- 源快照（最新 seq、transcript_updated_at）与计划时一致；
- 状态仍是 2，indexed_seq 和行数也与计划时一致。

### 单测（`lab/transcript-projection-incremental.test.mjs`，5/5，已进 catalog）

- release 文件等于补丁器作用在 V 字节上的结果；锚点各命中一次；重复打补丁会报错。
- 追加器里的 5 处标脏都还在原位：前缀完好的写 2，未分类行写 1；追加器之外的写入方不变。
- 等价性：以 V 原版的全量重建为真值。先用全量重建发布前 k 行的投影，再插入一段或两段后缀，标成 2。
  - 后缀覆盖 13 种形状：分叉、回退（含 appendParentId 指向叶子控制）、旁路 custom、旁路 message、叶子指向 null、reset、过期父节点、没有 parentId 的行、非 canonical 带 parentId 的行、无效叶子控制、压缩后从检查点之前分叉、线性追加。

- 不出增量计划的情况：状态为 1、旧投影缺行、watermark 未知、存在未分类行、没有新行。计划之后有写入时，应用会被拒绝。
