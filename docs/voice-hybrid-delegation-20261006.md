# 小何 / Grok 混合执行候选

PR 217 的直接工具和静默提示修复保持独立待发布。此补丁只在 Candidate 开发、验证，尚未获准合 dev、部署共享 VLab 或 V。

## 执行路径

- 简单请求：语音模型选择 `memory_search`、`web_search`、飞书日历等原生工具；不增加一次后台模型推理。
- 复杂请求：模型调用 `delegate_to_v(question, context)`，完整目标交给当前配置的 Makaron/V 后端，通过标准 `chat.send`、`agent.wait`、`chat` / `agent` 事件承接。
- 后端绑定本人既有飞书 session；每个委派由服务端产生独立 idempotency/run ID。同一电话同时只接一个后台目标，保留现有后端模型、工具策略和授权。
- 后台公开 commentary 的完整句子可以阶段播报，不转发 reasoning、工具原始输出或未完成句子。原有观察器去重，播报最多每十秒一次；等待用户/模型讲话和实际浏览器播放结束。进度使用供应商原生语音事件，小何 `speech_text_buffer.commit`，Grok `force_message`（可打断），不伪造 assistant PCM。
- 委派工具立即返回 accepted/working，结束语音端的工具等待；实际后台 run 独立继续，等待时普通插话不调用取消。只有匹配 run 的终态或持久化消息才能触发最终语音。小何使用真实请求/回答成对补充上下文并原生 TTS，Grok 使用原生 force_message 主动返回；小何字幕标明 V-backend 来源，不把 host 字幕当供应商生成证据。
- 取消/挂断按 exact run 请求 `chat.abort`，并用 `agent.wait` 观察终止；不能用取消 ack 代替退出证据。确认不了退出时保留责任、阻止新委派；不取消整个个人 session，更不取消别人的 run。迟到结果不能续传。

## 验证范围

本地覆盖直接查询不委派、完整目标一次派发、公开进展筛选/去重、播放期间延期、同时聊天、终态/持久化结果核对、取消/迟到隔离及未确认取消的重试。

真实 Candidate 必须分别验证小何和 Grok：原 H5 用户输入 → 直接记忆工具；复杂请求 → 实际 V run 与多个后台工具 → 阶段供应商 PCM/浏览器播放 → 不需要催促的最终语音；另一个长任务 → 原生取消 → exact run 终态。候选结果独立记录，测试脚本、健康、本地通过不表示真人验收。

当前暂停的最终答案严格保真、双向声学/AEC、旧 barge/父子续传严格门槛不改成通过。本补丁也不宣称所有复杂目标（尤其异步子任务的父子续传）均已验收。后台补充条件和任务跨通话持久化后续单独考虑，普通闲聊不会自动改写后台目标。

Grok 进度语音事件依据 [官方 Speech to Speech 文档](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech#force-message)。共享和 V 等待用户通知，保持原 `/voice` 链接及 Web/H5 布局。

## 第一轮实际诊断

25fe0c15 的独立 Candidate 原 H5 样本保留失败：小何确实发起原生 memory_search 和一个真实 V run，但工具调用一直挂起等待，供应商约 33 秒报 AudioTTSIdleTimeoutError，host 已对该 exact run 取消并观察 error/rpc 终态。首次脚本也过早用音频空闲代替工具完成，且未声明工具事件订阅；Grok 使用已有个人上下文回答了重复问题，没有产生这一轮新记忆调用。这些不能称完整混合执行通过。

后续修复复用小何已有 willContinue 工具续传：先发送 working 回执释放挂起状态，实际后台完成后通过同一工具身份返回最终内容；音频段实际完成时允许继续播报。网关连接声明 tool-events，以真实后台工具结果作为阶段播报的前置证据；首条纯计划不播。脚本等待实际工具交付，独立 USER 输入明确要求重新搜索。原样本和音频不改写，新样本单独记录。

## 第二轮诊断与异步收尾修复

fa1da9f8 原 H5 第二轮两个模型均有新的真实直接 memory_search，且一个配置的 V run 自动执行记忆原文、Web search、sleep/date，并返回完整最终结果。Grok 闲聊笑话和真正公开进展有原语音记录，取消实际 V run 已观察 terminal；但独立复查发现最终答案没有真正语音返回，不能据脚本 hybrid-completion 检查称全链通过。小何续传避免了初轮 33 秒超时，但闲聊未回答，最终播放空闲检查失败。其整个样本 PCM 长约 86 秒，旧 60 秒播放空闲截止不足以单独判断供应商故障。旧 FAIL、脚本汇总和音频保留不改。

80113b57/943acdea 改成两个模型都先回 accepted/working，host 持有后台任务，完成后原生主动播报，避免闲聊后给旧工具输出却不产生新回答。真实复验要求出现用户请求的小汽车笑话且发生在后台完成前，原脚本的“任何 assistant 内容”条件已移除。长答播放观测扩大到 120 秒（依据原 PCM 时长），语音队列和 AEC 门槛未修改。

后台 exec 返回的 running sessionId 纳入本电话所有权，取消时先确认 run 停止并收齐已启动 exec 的返回，再 kill/poll 这些已确认的执行会话。迟到 exec 返回仍可用于清理，不进入语音；不能确认工具返回时保留后台责任，阻止新委派。当前只证明本地回归；新真实场景另行记录，不能用前一版通过项代替。

## 第四轮真实结果与当前边界

4349c4f6 同一隔离 Candidate 中，小何原 H5 通过新的直接记忆查询、真实 V 后端完整多步任务、后台未完成前正常回答小汽车笑话，以及实际进展和最终原生语音。一个 run 自动执行 14 个后台工具事件，最终播放正常收尾。

取消仍失败：agent.wait 已观察 exact run 终态，但通过 Gateway 直调 process 无法找到 Worker 创建的 neat-breeze；返回 No session found/failed 后，独立 /proc 仍看到同一 PID/startTicks。之后 PID 消失不能改写原失败。当前修复只让此类查询错误保留清理责任，不再谎报取消成功；跨 Worker 的正确执行会话控制还未完成。Grok 的完整原 USER 虽明确要求后台，仍自己使用原生工具完成目标，未产生 delegate_to_v，本轮委派路由失败。

后续补丁强化用户明确后台请求必须委派，并单独复验 Grok 核心路径；该样本只验证直接工具、后台闲聊、自动最终返回和公开进度，不覆盖或替代原取消失败。共享、生产和 PR217 发布仍等待用户通知。

## Grok 核心复验和隔离收尾

f6217211 新原 H5 样本只选择 Grok hybrid-core（不包含取消）。五项核心检查通过：接通问候、直接记忆、后台未完成前回答小汽车笑话、单一 V run 自动多步执行及最终原生语音、真实工具结果后的阶段播报。独立原 audit/供应商字幕/PCM 复查确认这一轮实际后台工具结果和音频返回，电话已正常关闭；严格最终保真、物理 AEC 和真人听觉未重新验收。小何核心证据来自 4349c4f6，不能称 f621 最新整包双模型全面验收。

## 真人试用回归修正

cbf3c46c 真人试用失败：小何三个查询都先口头说“我查一下”后结束当前轮；约 22、29、32 秒后用户催促才选择 memory_search。原生调用实际存在，没有委派后台；第一次工具耗时约14秒，后两次约1.3和2.6秒，不能把等待全部归于工具。旧通过样本不代表这一版真人体验通过。

当前修正让小何先在同一轮选择原生工具，由 direct-only host notice 使用真实供应商语音说明任务开始；真实工具立即执行，快结果等待说明语音实际结束后再续传。后续工具不重复说明，新用户话轮重新允许一次说明；插话或原生取消释放 notice 等待。普通原生 Talk/GPT Live 路径不启用此 hook。

两模型共享 H5 PCM 播放由10毫秒启动余量改成180毫秒抖动缓冲；相邻帧保持连续时间排程，只在真正耗尽后重新缓冲，记录浏览器 underrun、收帧间隔和队列大小。不是 AEC/双向修复，也不据此宣称真人卡顿已解决。当前192项相关本地测试通过；原真人失败、未确认取消和暂停的保真/AEC门槛保留。
