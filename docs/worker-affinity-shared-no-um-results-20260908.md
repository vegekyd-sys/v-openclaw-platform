# worker-affinity.1：共享 VLab 关闭 UM 专项验收通过

2026-09-08。结论限定为 **UM 关闭时的 Worker 调度/复用专项验收通过**。生产未修改、未部署；不等于 UM 故障修复或所有发布门槛通过。

## 本轮执行

- 用户明确要求直接在共享 VLab 修改并验收，不再混入 UM 连接问题。
- 协调方明确无占用/部署计划后获取 integration lease。沿用现有独立集成源码与共享实例，不新建/复制私有实例或数据库。
- 三组始终使用同一约 2.58 GB 完整 Makaron Agent 数据库，DeepSeek v4 Pro、原生 Worker、两个 Worker × 三个槽、主并发上限五。CPU/内存限制不变。
- Gateway 与 Worker 两份配置的 UM 都禁用；其他工具/模型不变。每条请求的阶段日志均可关联；三组各 95 次请求中 UM connect-start 均为零。
- 工具路径是实际本机 exec 读取 UTC 时间，每轮加入唯一请求编号；同时核验当轮 toolCall、匹配的成功 toolResult、时间戳和编号，不接受复用上一轮结果或只口头答完成。
- A → B → A2 各 95/95，合计 **285/285 请求、123 次真实本地工具调用、30 轮五并发全部通过**；另有烟测 3/3。本矩阵无失败或超时。
- 本地调度、生命周期、扩容、取消/超时隔离相关回归 16/16 通过，测试时启用 affinity 开关。它们不冒充真实渠道测试。
